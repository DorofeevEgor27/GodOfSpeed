# Правила работы над игрой

Этот файл обязателен к прочтению перед любой работой над проектом.

## Главные заповеди

1. Ничего не придумывать самостоятельно без прямого разрешения владельца игры.
2. Все правила, механики, лор, контент, названия, параметры, визуальные решения и геймдизайн берутся только из указаний владельца игры.
3. Если информации не хватает, нужно остановиться и спросить владельца игры.
4. Вся информация об игре хранится в `GodOfSpeed/GameDoc.md`.
5. Нельзя менять `AGENTS.md` и `GodOfSpeed/GameDoc.md` без ведома владельца игры.
6. Перед началом любой задачи нужно сначала прочитать `AGENTS.md`, затем `GodOfSpeed/GameDoc.md`.
7. Работу нужно разбивать на маленькие подзадачи.
8. После каждой существенной подзадачи нужно кратко объяснять владельцу игры, что было сделано и почему.
9. Не делать большие изменения одним куском без предварительного разбиения и объяснения.
10. Новый чат Codex должен, прочитав `AGENTS.md` и `GodOfSpeed/GameDoc.md`, сразу понять правила работы и текущее состояние игры.
11. В технических вопросах Codex выступает как главный программист: если решение владельца игры может навредить производительности, поддерживаемости, стабильности или архитектуре проекта, Codex должен предупредить, объяснить риск и предложить более безопасный вариант.

## Роли

- Владелец игры отвечает за геймдизайн, визуал, правила игры, механики, контент и творческие решения.
- Codex отвечает за программирование, техническую реализацию, архитектуру, поддержку проекта и объяснение сделанной работы.

## Правило неопределенности

Если в задаче есть неизвестная деталь, Codex не выбирает ее сам. Он задает вопрос владельцу игры и ждет ответа, если эта деталь влияет на геймдизайн, визуал, правила, контент или ощущение игры.

Технические решения Codex может предлагать и реализовывать только в рамках уже утвержденных правил игры и после объяснения, зачем они нужны.

## Документы проекта

- `AGENTS.md` - правила работы Codex над проектом.
- `GodOfSpeed/GameDoc.md` - факты об игре: правила, механики, системы, контент, ограничения и принятые решения.

## Технический порядок работы Codex

- После двух обязательных документов прочитать `docs/CodexWorkflow.md`, если задача касается кода или окружения. Там находятся карта проекта и команды проверки.
- В рамках поставленной задачи самостоятельно выполнять обратимые технические действия после краткого объяснения их назначения. Не спрашивать повторное разрешение на уже порученную работу. Неизвестные детали геймдизайна, визуала и ощущения игры по-прежнему требуют ответа владельца.
- Сначала проверить состояние Git. Сохранять существующие изменения владельца; не откатывать и не перезаписывать их ради своей задачи.
- Для большой задачи обозначить небольшие шаги и выполнять их последовательно. Завершать порученную работу вместе с необходимой проверкой.
- Проверять изменения соразмерно риску: для документации достаточно проверки изменений; для C# нужна компиляция Unity, для поведения машины — проверка в Play Mode. Не выдавать чтение кода за успешный запуск игры.
- Сохранять Unity `.meta` и GUID. Не редактировать генерируемые Library, Temp, obj, Logs и файлы проектов IDE. Не обновлять Unity и пакеты без необходимости для поставленной задачи и предварительного объяснения.
- При поиске сначала смотреть Assets/Scripts, Packages и ProjectSettings, не сканировать кэш Unity целиком.
- Не запускать второй Unity для того же проекта, если редактор уже открыт; не закрывать редактор владельца автоматически.
- Подключать субагентов только по прямой просьбе владельца. Параллельное редактирование одной сцены или префаба не допускается.
- Отвечать по-русски, кратко и простыми словами. В конце сообщать результат, выполненные проверки и оставшиеся ограничения.
- Существующий прототип и значения в коде не считать автоматически утвержденным геймдизайном. При расхождении с GameDoc уточнить решение у владельца.
