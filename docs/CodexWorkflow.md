## Окружение и проверки

Из корня репозитория в PowerShell:

```powershell
& ./tools/Check-Environment.ps1
git -c safe.directory=C:/GodOfSpeed status --short
git -c safe.directory=C:/GodOfSpeed diff --check
```

Исключение safe.directory здесь действует только для конкретной команды и конкретного локального репозитория. Оно нужно при запуске Codex от отдельного пользователя песочницы; глобальное доверие ко всем репозиториям не требуется. В другой копии использовать ее фактический абсолютный путь.

Диагностика проверяет версию Unity, наличие редактора, Git и корректность JSON пакетов. Она не компилирует игру и не заменяет Play Mode.

После изменения C# дождаться компиляции в Unity и проверить Console. После изменения движения машины дополнительно проверить соответствующий сценарий в Play Mode. Если доступа к редактору нет, явно указать непроверенное поведение. Пакет Unity Test Framework уже указан в manifest; наличие пакета не означает наличие тестов.

Для закрытого проекта компиляцию можно запускать редактором нужной версии с `-batchmode -quit -projectPath <абсолютный путь к GodOfSpeed> -logFile <путь к журналу>`. Перед запуском проверить, что этот проект не открыт. Оценивать и код завершения, и журнал. Тесты запускать отдельно, только если есть подходящие тестовые сборки.

Обычный `dotnet build` не считать заменой проверки в Unity. Установленный отдельный .NET SDK не определяет версию компилятора Unity. Не устанавливать дополнительные SDK и плагины без конкретной технической потребности.

Для проекта выбран GPT-6 Astra, уровень рассуждения high; для планирования также high. Это исходный инженерный выбор для этого проекта, а не гарантия идеального результата. Для коротких вопросов можно выбрать low, для особенно сложной диагностики — повысить уровень в интерфейсе. Существующая задача может сохранять выбранные в интерфейсе настройки; настройки файла проверять при создании новой задачи.

Лучше задавать результат, ограничения и способ проверки. Пример:

«Исправь [наблюдаемую проблему]. Сейчас происходит [что], ожидаю [что]. Не меняй [ограничения]. Проверь [сценарий]. Техническую реализацию доведи до конца; если не хватает игрового решения, спроси меня».

Одну связанную работу вести в одной задаче. Для новой независимой работы создавать новую задачу с доступом к этому проекту. Передавать сообщения Console, шаги воспроизведения и нужную сцену. Для визуальных задач прикладывать изображение и конкретно указывать желаемое изменение.
